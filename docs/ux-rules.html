Warden · new feature

Custom guardrails and rules

Today you can only switch rules on or off. Rules can be added only in each repo's .warden.yml, and the review instructions can't be set from the app. Three ways to add a real editor. Pick one or mix parts, then I build it into v1.0.0.

What every variant adds

  1. New rule: name, what to check, and how. A Claude rule is a plain-English instruction added to the review. A pattern rule is a regex run over added lines. A semgrep rule points at a rules file.
  2. Severity, which files it applies to (glob), and on/off
  3. Test box for pattern rules: paste code, see which lines match before saving
  4. Edit, duplicate or delete your own rules. Change severity or scope of built-in and .warden.yml rules without editing the repo
  5. Review instructions: free text added to every review for the project (the extra_instructions setting)

How it is stored

  1. Custom rules are saved as project overrides, which already merge rules by ID
  2. The repo's .warden.yml stays the shared source; your rules sit on top
  3. "Export to .warden.yml" copies the YAML so you can commit it for the team
  4. New rules get IDs like CR-001 so they never clash with FR-/SEC- rules
